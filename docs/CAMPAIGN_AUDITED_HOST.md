# Optional audited principal host

`ciw.services.open_audited(facade, chain=..., read_anchor=...,
compare_and_set_anchor=...)` wraps an existing `PrincipalFacade`. The launcher
must supply the bounded `AuditChain` and durable independent anchor callbacks.
The wrapper adds no tool, resource or scientific permission. The underlying
facade still reads current policy immediately before dispatch.

The chain records a host-generated correlation identifier, canonical operation,
UTC timestamp, principal/request/result hashes and effect state. It never accepts
raw requests, results, credentials, private corpus or exception text as events.
Discovery is limited to the intersection of current grants, bound profiles and
the chain's allowed operation names. A resource read additionally requires
`resource_read` in that host-selected journal scope and existing resource grants.

An audit `admitted` event means journal admission, not execution authorization.
Known tool calls denied by current policy are recorded as refusals with no host
dispatch. Unknown names and invalid oversized/non-JSON inputs refuse before
journal admission. A returned refusal does not assert rollback.

SDK launchers may pass a stable `call_id` to `AuditedPrincipalHost.call` or
`invoke`; tool arguments cannot set it. MCP correlations are generated by the
server. A repeated recorded ID never reexecutes: use the underlying existing
inspection APIs to inspect an operation's outcome. Unresolved prior calls block
fresh correlations across restart, so a new ID cannot erase uncertain custody.

Sink/anchor failure before dispatch prevents execution. Failure after returned
effects produces `outcome_unknown` and a hold. Reconciliation is a separate
host-only audit API requiring a closed record, exact prior-record binding and
independent custody validation. No MCP tool clears it; no automatic replay or
rollback is promised. A filesystem copy is not an independent trust anchor.

This wrapper is opt-in. Existing hosts, policies, deployment configuration and
execution holds remain unchanged until a launcher explicitly binds it. Local
tests use real SQLite transactions as an independent test anchor; that fixture
does not establish remote durable storage or backup/disaster recovery.

See [the process/audit contract](CAMPAIGN_PROCESS_AUDIT.md),
`tests/test_campaign_audited_host.py` and `tests/test_audit_chain.py` for actual
MCP/SDK, current-policy, sink failure, restart and reconciliation tests.
