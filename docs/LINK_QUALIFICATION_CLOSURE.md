# Link: qualification dependency closure

Extends the existing installation qualifier at `e6252599851024e832266e2632ae85b7a8f5a2ef`.


The installed qualification gate no longer maintains a second hand-written list
of pins or copied packages. It derives the existing base, `dev` and `legibility`
requirements from the exact `pyproject.toml`, checks them against the selected
NET wheel's metadata, and follows active installed `Requires-Dist` relationships
using their environment markers and requested extras. Unrequested extras are not
activated. This inspects the already supplied environment; it does not resolve,
download, upgrade or replace a dependency.

This repairs a reproduced coverage gap: the previous gate checked four direct
pins but omitted the declared `PyYAML==6.0.3` development requirement from both
its pin gate and isolated copy. Its real isolated interpreter therefore could
not import `yaml`, even though source-host tests had access to it. The current
gate includes all five active direct project pins and the full selected library
closure. The library list can change with dependency metadata without editing a
second hard-coded list.

Missing distributions, unsatisfied transitive constraints, conflicting direct
pins, active direct URLs, unknown requested extras, incompatible Python
requirements, or disagreement between project and root-wheel metadata refuse.
Dependency traversal is bounded to 64 distributions and reaches a fixed point
for cycles and extras arriving along multiple paths. It imports no target
application merely to inspect metadata. PyPA's optional `Requires-Python` field
is not fabricated when absent on a dependency.

The qualification receipt records required and actual versions, direct-pin
deviations, active extras and metadata references. Metadata references hash the
text returned by `importlib.metadata`; separate file records retain exact copied
bytes. The copied environment rechecks that same selection and runs real
`pip check`. The latter checks base package compatibility; the explicit metadata
walk separately checks the selected extras. Library-file hashes are checked
before and after the original installed tests/operator journeys, so unchanged
version labels cannot hide a modified recorded library file.

`--require-pins` remains fail-closed. `--allow-host-dependencies` can run labelled
development tests with recorded direct-pin differences, but does not waive a
broken transitive constraint or root-metadata mismatch. A nonzero `pip check`
result remains `INCOMPATIBLE_DEVELOPMENT_ENVIRONMENT`, not a dependency pass.
Passing the scientific/software test suite in this mode is still not a pinned
release qualification.

| Internal check | Regression |
| --- | --- |
| LQ-DEP-01: no omitted direct pin | Project YAML-like fixture, actual PyYAML import and complete direct selection |
| LQ-DEP-02: active closure and root metadata agree | Transitive constraints, cycles, extras, markers, root-metadata drift, bounded traversal |
| LQ-DEP-03: unknown/missing inputs cannot become PASS | Missing-dependency BLOCKED receipt before environment creation; explicit pin deviations |
| LQ-DEP-04: recorded library bytes remain stable | Changed/missing/symlink file rejection and pre/post installed-run byte checks |

This extends the existing qualification script and workflow, not the Link/NET
application or installer. It still copies reviewed host distributions for the
qualification sandbox and excludes their generated bytecode and external
command wrappers. It is not publisher authentication, CVE clearance, bootstrap
attestation, complete filesystem inventory validation, or protection against a
malicious concurrent host. Production package provisioning remains the separate
hash-locked wheel path described above. Measurement, calibration, timing, safety,
EMC and release obligations are unaffected.
